nxdk_low_level_cpu_tests · hakuX-lr

hakuX-lr's CPU against an Xbox, test by test

Each suite checks the x87 FPU, SSE and MMX of the emulated Pentium III against the values a real Xbox 1.0 produced; a test passes when all of its checks do. hakuX-lr runs the guest's code two ways: on an x86-64 host directly on the host's CPU (KVM), on an ARM host translated by FEX. Each is listed below with its failing checks.

x86-64 · KVM · AMD Ryzen 7 9800X3D

hakuX-lr master (223d3c0, after 0.28.0; local build), RetroArch 1.22.2 on Linux, 2026-11-15. The guest's x87, SSE and MMX instructions run on the host's CPU (Zen 5) under KVM, so the results are that CPU's where it differs from the Xbox's Pentium III (Coppermine). Two differences are corrected: AMD's RSQRTSS and RSQRTPS give other approximations than Intel's, so hakuX-lr finds those instructions in the title's code and gives them the Pentium III's results; and a new thread starts with the x87 at 53-bit precision, as the console's kernel sets it (PR #230; the 0.28.0 release started threads at 64-bit precision and failed 11 TestFloat F64 checks).

ARM64 · FEX · Retroid Pocket Nova (Snapdragon 8 Gen 2)

hakuX-lr master (1361cda, after 0.36.0; local build), RetroArch on PortareOS (20261120), 2026-11-20. The guest's code is translated to ARM64 by FEX, so these results are FEX's emulation of the Pentium III's x87, SSE and MMX. Since the 0.36.0 release (8 of 15): RCPSS and RCPPS return Intel's table values; MXCSR and the x87 status word report their exception flags; COMISS, MINSS, MAXSS and FCOM raise invalid for a NaN; a square root's NaN has the sign x86 gives it; and a float store follows the x87's underflow rule.

Same device and hakuX-lr master build (1361cda) as the column before, started with NC_FEX_X87=80: FEX's full 80-bit soft-float x87 instead of hakuX-lr's default reduced x87 (host doubles). Slower; not the default. The x87 status word's exception flags are the reduced x87's only, so TestFloat fails here. 2026-11-20.
